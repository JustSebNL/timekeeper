# Project landscape

1. Identify the outcome, constraints, users, dependencies, and acceptance evidence.
2. Create Categories for durable functional areas.
3. Create Tasks for outcomes, not vague activities.
4. Split each Task into bounded Sprints with explicit estimates.
5. Record dependencies, risks, and the next recommended action in a Project note.
6. Verify the result with `tk tree <project-id>` and `tk summary <project-id>`.

Do not call a project planned while its next executable Sprint is undefined. Keep speculative ideas in a separate note or Task, clearly marked as hypotheses.
