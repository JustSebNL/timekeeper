TimeKeeper Documentation

Help agents stay oriented when project work outlasts a single chat.

📋

Durable Project Records

Keep the project goal, next action, and current progress in one place that persists across sessions and agent handoffs.

⚡

Sprint-Based Execution

Break long work into small, finishable steps with active-time tracking. Start, pause, resume, or complete each Sprint.

🔌

Plugin Architecture

Extend TimeKeeper with subprocess-isolated plugins. Plugins communicate through the versioned REST API and can never crash Core.

🤖

Multi-Agent Ready

Give several agents a common local view of a Project. FASE identity attribution tracks which agent made each change.

Quick Start

# Build and install
go install ./cmd/tk ./cmd/server

# Start the server
timekeeper -addr 127.0.0.1:1618 -db .timekeeper/timekeeper.db -ui web/index.html

# Create your first project
tk p new "My Project"

# View the dashboard
open http://127.0.0.1:1618/

Projects API

GET /api/v1/projects

List all projects.

Response

[
  {
    "project_id": "P-10000",
    "name": "My Project",
    "alias": "my-project",
    "status": "Active",
    "created_at": "2026-10-01T08:00:00Z"
  }
]
POST /api/v1/projects

Create a new project.

Request Body

{
  "name": "My Project",
  "alias": "my-project"
}
GET /api/v1/projects/{projectID}/execution-tree

Return the full execution hierarchy: categories → tasks → subtasks → sprints.

GET /api/v1/projects/{projectID}/handoff

Generate an agent handoff snapshot with active sprints, recent messages, and unblocked work.

POST /api/v1/projects/{projectID}/tasks/batch

Create multiple tasks in a single request.

Request Body

{
  "tasks": [
    { "category_id": "C-10001", "name": "Task A", "estimated_duration_seconds": 3600 },
    { "category_id": "C-10001", "name": "Task B", "estimated_duration_seconds": 1800 }
  ]
}
